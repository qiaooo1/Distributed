# Java 面试如何讲 JobLab

## 60 秒介绍

我做了一个纯 Java 的多租户分布式任务调度平台，以销售报表导出为业务样例。运营人员可以提交即时、延时和 Cron 任务，管理员管理租户成员和审计。调度器把派单状态和 Outbox 一起持久化，经 RabbitMQ 派给多个 Worker。任务领取时校验租户并发配额并发放租约，宕机后会按退避规则重新派发，只有当前租约可以写入结果。我会现场展示同键跨租户隔离，以及停止一个 Worker 后另一实例接管。

## 面试追问

| 问题 | 结合实现回答 |
| --- | --- |
| 如何防止越权查其他租户的任务？ | JWT 确认身份，账号表确认当前权限，任务、调度、成员和审计 SQL 都按 tenant_id 查询。不同租户可以提交相同的幂等键 |
| JWT 已经发出去，权限变更怎么生效？ | 更新账号版本和角色，每次校验时读取当前版本。旧令牌即使尚未到期也会被拒绝。代价是每次已认证请求产生一次账号查询 |
| 两台调度服务会重复生成日报吗？ | 调度行在事务内用 SKIP LOCKED 竞争，推进 next_fire_at 和生成子任务同事务完成，(schedule_id, scheduled_fire_at) 是最终唯一约束 |
| 系统停半小时会补多少任务？ | 以可配置阈值划分迟到触发。SKIP 直接跳过，FIRE_ONCE 折叠为单次补跑。选择 SKIP_IF_ACTIVE 时，仍未完成的上一轮会使本轮跳过并写审计 |
| 为什么任务进了 MQ 还要领取？ | Broker 负责投递。领取同时校验 generation、任务状态和租户配额，把并发限制以及执行授权落到数据库 |
| Broker 收到事件后进程挂了怎么办？ | 发布器没来得及写 sent_at，Outbox 会重发。重复消息的 generation 和当前状态决定它能否领取 |
| 旧 Worker 迟到回写会发生什么？ | MySQL 行锁内校验租约令牌和时间。旧执行可能仍在计算，只有当前执行的提交能写入结果。重放同一个已提交完成请求仍返回已接受 |
| 如何避免某个租户抢完 Worker？ | 按租户锁住额度行并统计有效租约，超额任务回到 SCHEDULED 等待。该措施限制并行度，高流量时仍需要队列分片和公平调度策略 |
| 怎么排查任务卡住？ | 用任务状态和 attempts 区分等待、消耗和续租。Prometheus 看 Outbox 最老时长、过期租约、实例健康，再检查 RabbitMQ DLQ |
| 现在的瓶颈和改进方向？ | Outbox 在等待确认时持有行锁，同租户领取在租户行串行化。高吞吐可以批量异步确认并按租户分片，先用压测观察锁时间和延迟分布 |

## 演示顺序

1. 以 operator 提交一份日销售汇总，展示 202、任务详情和 CSV。
2. 登录另一个租户，使用原幂等键提交，展示新任务，以及查询原任务的 404。
3. 登录 viewer，展示能查询本租户数据，提交任务被拒绝。
4. 创建 Cron 任务，观察自动生成 job、审计事件和调度游标。
5. 停止当前处理报表的一台 Worker，检查第一次 LEASE_EXPIRED，第二次 SUCCEEDED，另一实例接管。
6. 用管理员查询审计，通过 X-Request-Id 对应同一请求，最后打开监控查看积压规则。
